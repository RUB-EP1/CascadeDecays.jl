# Rendering documentation

All documentation notebooks use the same local workflow. From the repository root:

```sh
julia --project=docs -e 'using Pkg; Pkg.instantiate()'
quarto render docs/<name>.qmd --to gfm
```

If Quarto reports an out-of-sync Julia environment after dependency changes, run
`julia --project=docs -e 'using Pkg; Pkg.resolve()'` and retry.

For example:

```sh
quarto render docs/compass-basis.qmd --to gfm
```

Quarto executes the notebook and writes `docs/<name>.md` beside its source,
plus `docs/<name>_files/` when there are figures. Review and commit the source,
Markdown, and referenced figures together. Edit the `.qmd`, not its rendered
Markdown. The COMPASS notebook includes the standalone numerical validation
script so its test output is regenerated by this command.

To render all documentation notebooks locally, use `quarto render docs --to gfm`.
The list is in `docs/_quarto.yml`. Examples use the same command pattern with
`examples/<name>.qmd` and their own Julia environment; see
[examples/README.md](../examples/README.md).

## Publishing with Documenter

```sh
julia --project=docs docs/make.jl
```

This step reads the committed Markdown and figures. It does **not** execute
Quarto or notebook computations. CI runs this same publishing step and does
not need Quarto. As before, deployment is handled by Documenter when running
in an authorized CI deployment environment.

`docs/prepare-pages.jl` lists published notebooks. It copies their rendered
Markdown into the ignored `docs/.documenter-src/` directory, adds Documenter
anchors and edit links, and copies figures. Missing renders or referenced
figure directories cause an error containing the exact local render command.
The resulting HTML is in `docs/.documenter-build/`.

Handwritten Documenter pages stay in `docs/src/`. There are no separate
`docs/generated/` outputs or notebook-generated copies to maintain in `docs/src/`.

For a new notebook, add it to `RENDERED_PAGES` in `docs/prepare-pages.jl`,
the navigation in `docs/make.jl`, and the optional batch-render list in
`docs/_quarto.yml`. Render it locally and commit the outputs.

## Maintenance before major releases

Before every major release, **regenerate and review all documentation notebooks,
tutorials, and examples locally** against the release candidate. This is required
to catch broken examples, API changes, numerical discrepancies, and drift between
the explanatory text and the actual results. A passing documentation CI build is
not sufficient: it only publishes saved outputs.

1. Refresh the `docs` and `examples` Julia environments for the release candidate.
2. Run `quarto render docs --to gfm`, and render every `examples/*.qmd` notebook
   with `quarto render examples/<name>.qmd --to gfm`. Check that the batch list in
   `docs/_quarto.yml` includes every documentation notebook.
3. Review execution logs, assertions, and changes to the generated Markdown and
   figures. Investigate warnings, unexpected numerical changes, missing output,
   and discrepancies between the prose and the results; do not accept regenerated
   outputs solely because rendering completed.
4. Run `julia --project=docs docs/make.jl` and inspect the resulting HTML, including
   equations, tables, plots, navigation, and cross-references.
5. Fix any problems and rerender affected notebooks. Commit the reviewed sources,
   Markdown, and figures together before tagging the release.
